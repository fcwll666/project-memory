# 资源与数据来源核对

目标是让后续助手能找到并判断现有资源是否可以复用。仅盘点项目范围内、与当前阶段有关的内容。

## 核对顺序

1. 从现状和已有索引找文件。先读取仓库入口、版本信息、目录清单和既有报告，再按当前问题查选定脚本、日志或数据描述。大型原始数据、权重和日志优先用元数据和已有汇总。校验值能解决文件版本或同名文件歧义时，再做有针对性的比较。
2. 连接远程目录时使用用户提供或项目已配置的 SSH 别名和现有认证。启动前核对实际主机、身份和项目根目录，再用现有 SSH MCP 或系统 SSH 读取相关资源。新会话里工具登记与可调用性分别确认。连接失败时继续用可用的本地资料，说明远程状态的核实范围。
3. 找来源时优先取下载记录、元数据、锁文件、代码里的实际输入和处理日志。对话里推荐的地址只记录为候选来源。文件存在能确认该副本存在。要把它归到某个下载源，需要下载记录、版本标识、可靠校验值或其他能建立对应关系的材料。
4. 给可复用数据记录原始来源链接或访问编号、版本、获取方式、保存位置，以及相关筛选或转换脚本、参数和输出。样本范围、标签口径或格式不同的同名版本分别记录。信息无法核实时，在相应字段上直接说明缺什么，保留候选线索。
5. 记录能帮助继续实施的环境和接口细节，例如实际解释器、依赖版本、关键参数、输入格式、输出路径。用户已有模板时补入原位置。原始数据、凭据和无需归档的终端输出留在原处。

## 记录示例

以下是虚构项目。旧对话建议下载 A 或 B，目录中已有 `data/raw/cohort.tsv`，预处理脚本确实读取它，但没有当次下载记录。

| 项目 | 可保存的记录 |
|---|---|
| 数据 | `data/raw/cohort.tsv` 存在，当前下载源及版本未核实。候选来源 A、B 见历史会话对应段落。 |
| 处理 | `scripts/prepare.py` 读取该 TSV，输出 `data/processed/split.json`，划分参数见脚本配置。 |
| 已完成 | 本地 `results/baseline/metrics.json` 和对应日志已核对。 |
| 尚待核实 | 主会话报告另一次运行完成，目前没有找到该次运行的产物。 |
| 接续 | 从已核实的 baseline 结果绘制基准图。对比图需要先找到第二次运行的结果。 |

如果文件未找到，记录查过哪些范围和哪些目录仍不可访问。只读核对中发现缺失文件时，可以保留待查任务，按本次授权处理后续操作。
